# 模型任务记录系统 v0.147 源码

## v0.147 变更一览

### 稳定性与性能
- **B1+B2 主进程写入串行队列 + 强制只读锁**：所有写盘操作（`db:save`、自动/手动备份）走 `enqueueWrite` Promise 串行队列；数据文件初始化失败时 `__readOnly=true`，拒绝一切写入，避免空库覆盖真数据。
- **B3 全局错误捕获**：页面顶部注入 `window.onerror` + `unhandledrejection`，错误写入 `window.__errLog` 并 toast 提示。
- **B4 备份完整性校验**：备份写入后回读 `JSON.parse` 校验，损坏的备份文件自动删除。
- **B6 保存节流**：`save()` 防抖 300ms，连续编辑只写一次盘；撤销/重做/关闭窗口走 `persistNow()` 立即落盘。
- **A7 taskMetrics 缓存**：按任务 id 缓存，`save()` 时版本号自增使缓存失效，列表渲染不再重复计算工时。

### 新功能
- **C1 任务依赖与阻塞关系**：任务新增 `dependsOn` 字段，可在编辑任务时多选上游依赖。被阻塞的任务（有未完结的上游）不能推进到「制作中」及之后，列表/看板/详情页显示 ⛔ 阻塞标识和上游名称。多个任务可同时处于「制作中」，但同一工时时间段（dayTimes 重叠检查）仍只能分配给一个任务——这十分钟做 A、下十分钟做 B 是允许的，正好匹配「A 在等反馈时切去做 B」的场景。
- **C9 全局快捷键可配置**：在「设置 → 快捷键」里自定义 Ctrl+N 新建、Ctrl+S 保存、Ctrl+Z 撤销、Ctrl+Shift+Z 重做、Ctrl+F 搜索、Ctrl+K 命令面板、`/` 快速搜索、`?` 帮助。支持在输入框里直接按组合键录制，留空即禁用。
- **C2 工时到点通知**：每 30 秒检查今天各任务的工时段，到点弹系统通知 + toast 提醒。

- **C4 模型版本迭代记录**：模型详情弹窗可记录每次修改的版本号与说明。

## 文件说明

| 文件 | 作用 | 说明 |
|---|---|---|
| `index.html` | 主程序（全部功能都在这里） | 约 1.1 万行，单文件。**双击就能用**，不需要装任何东西 |
| `main.js` | Electron 主进程 | 负责读写 `C:\artvom` 下的数据、原子写入、备份、加密 |
| `preload.js` | 安全桥 | 只把允许的接口暴露给页面，其他一律拒绝 |
| `package.json.build.json` | 打包配置 | 用 electron-packager 打包 exe 时，改名为 `package.json` 放在 `index.html` 同级目录 |

## 三种用法

### 1. 只想用（最常见）
双击 `index.html`，直接用浏览器打开。数据存在 `C:\artvom`，功能完整。

### 2. 打包成 exe
把 `index.html`、`main.js`、`preload.js`、`package.json.build.json`（改名为 `package.json`）放进同一个文件夹，然后：

```bash
npm i -D @electron/packager@20.3.0 electron@45.0.0
npx electron-packager . "模型任务记录系统" --platform=win32 --arch=x64 --icon=app.ico --out=dist
```

> **v0.147 改了 `index.html`、`main.js`、`preload.js`**：浏览器打开 `index.html` 即用最新前端逻辑；若要出 exe，需重新打包（或替换 exe 目录下的三个文件），否则跑的还是旧逻辑。

### 3. 改代码
`index.html` 里所有逻辑都在一个 `<script>` 块中，搜索函数名即可定位。版本号在文件顶部的 `APP_VER`。

## 数据目录结构

```
C:\artvom\
├─ data\            主数据（任务数据.json 等，DPAPI 加密）
│  └─ 附件\          任务附件
├─ backups\         自动备份（明文，换机也能打开）
├─ task\            任务相关导出
├─ models\          模型库文件
├─ bridge\          Maya 桥接
└─ sync\            外部同步（export.json / import.json）
```

**重要**：`data` 下的文件是加密的，不要用记事本打开或另存，否则会被判定为损坏并进入只读保护。要备份请用程序里的「手动备份」，产物在 `backups\` 里，是明文的。

## v0.144 修了哪些问题（外部复查清单 21 条，全部核实并修复）

### 一、致命级

**1. 打包版 exe 读不到数据，首次保存就把真数据覆盖成空库**（最严重）
窗口开了「上下文隔离」，preload 里往 `window` 上挂的 `__DB_INIT__` 页面根本看不见——
打包版一直是以「空库 + localStorage」启动的，而且不进只读保护，第一次保存就把
`C:\artvom\data\任务数据.json` 覆盖掉。修复：改用 `contextBridge.exposeInMainWorld` 注入。
已在真实 Electron 环境验证：旧代码实测复现了「磁盘老任务被覆盖」，新代码读写盘全部打通。
⚠️ 如果你最近用打包版存过数据，建议翻一下 `C:\artvom\backups\` 里有没有早上的备份。

**2. 打包配置 `package.json` 的入口写的是 `index.js`，实际文件叫 `main.js`**
这是上一轮打包源码 zip 时放错的文件，已换成正确内容。

**3. 看板拖拽：确认框形同虚设，「已交付」永远卡死**
`appConfirm(...)` 之后没有 `return`，用户还没点确认，状态已经落盘；拖到「已交付」走的是
裸赋值，不触发「已交付→已完成」级联，也不写交付/完工时间戳；回退时确认框和回退窗还会
叠在一起。已重写：先校验 → 回退走专门弹窗 → 前进只交给统一的流转函数。

**4. 用模板创建的任务当场变「已完成」**
模板把「计划结束日期」塞进了 `endTime`（实际结束时间）字段，而系统规则是「有实际结束
时间一律强制已完成」。已改写进 `deadline`（截止日期）。

**5. 复制任务修了一半：副本当场变「制作中」且工时重复计**
副本带着原任务的开始时间（已过期→自动变制作中）和工时占用日期（同一天的工时被算两次）。
已全部清空，副本是一张干净的新工单。

**6. Maya 桥接整体瘫痪**
`startMayaWatch()` 全文件只有定义、零调用——心跳不轮询，「导入到 Maya」永远提示未连接，
Maya 回传的模型也不会自动入库。已在启动时拉起轮询并补一次收件。
